## Installable catalog entries

As of October 25, 2026, this `poc/appcontainer-skill-evaluation` branch contains six active entries in [SkillCatalog.xml](SkillCatalog.xml): the three production candidates and three pinned script candidates enabled only for isolated evaluation. Nine other candidates remain as XML comments. This branch is not the production catalog. The [AppContainer evaluation report](APP_CONTAINER_POC.md) records contained execution and deterministic CLI routing; real model selection and production AI-conversation integration remain unverified. The current chat does not execute installed Python/Node scripts or automatically configure MCP servers. The [eligibility criteria and pinned-source verification](SKILL_ELIGIBILITY.md) distinguish file installation, native discovery and actual feature execution. There are no listing or review states.

## Adding and removing a skill

Activate a skill after documenting its required execution path and qualification under the [current-host criteria](SKILL_ELIGIBILITY.md). Record a stable ID, an existing upstream skill directory, a full commit SHA and a license URL pinned to that same repository and commit. `Install.Mode` is `upstream`. To remove or defer a skill, comment out its entire `Skill` element and record a short reason outside or inside that comment. Encode consecutive hyphens in element text as `&#45;&#45;` so the raw block can become a valid XML comment; XML readers preserve the original text. XML comments never become marketplace entries. A catalog removal leaves existing local installations available to manage and remove.

## Deferral of new skills that receive credentials through environment variables

New submissions of skills that receive user API keys, tokens or client secrets through environment variables are currently deferred. Secrets in environment variables risk plaintext exposure and child-process inheritance, and TableCloth has not yet implemented per-skill credential storage and delivery. Submissions will resume after the corresponding features in [TableCloth #321](https://github.com/yourtablecloth/TableCloth/issues/321) are implemented and verified. See the [contribution policy](../CONTRIBUTING.md).

For functionality that works independently without a user key, specify the supported commands, output scope and additional dependencies separately from credential-dependent paths. New credential-delivery paths remain deferred even when an existing catalog entry also provides independently usable, keyless functionality. Do not suggest system or user environment variables, `.env` files or chat prompts as workarounds for the deferral. Never include real keys, tokens or client secrets in code, catalog entries, documentation or pull requests; use nonsecret placeholders in examples.

## Pinned versions and updates

Keep `Id`, `Source.Repository` and `Source.Path` unchanged when updating the same skill. Change `Source.Ref` to the new full commit SHA and change `License.Source` to the matching commit. Recheck required dependencies and update the qualification record and regression allowlist before activating that revision. The application compares the installed source commit with the current catalog commit to offer an update. A pinned Git commit does not pin packages downloaded later by upstream instructions. The commented NomaDamas candidates load instructions through an `npx` CLI, so those packages have their own version behavior.

## Skill files and execution prerequisites

Installing a skill copies its files and preserves the pinned license as `LICENSE.upstream`. It does not install runtimes, register MCP servers or configure API keys. The commented [Korean law skill](https://github.com/chrisryugj/korean-law-mcp/blob/4ccedb0dc89fce164493ffc9019b5ad35cb9b782/skills/korean-law/SKILL.md) requires a separately connected `korean-law` MCP server. The commented [jangbu entry](https://github.com/kimlawtech/korean-jangbu-for/blob/592f6d7c7be138ae578be9ed6769239cc527ddea/skills/korean-jangbu-for/SKILL.md) depends on a Python MCP server and sibling skills outside its installed path. A manifest without a script is not automatically an instruction-only skill. `Network` describes execution; remote installation always downloads files.

The optional [certificate-expiry skill](https://github.com/yourtablecloth/tablecloth-certificate-expiry) and [Windows Sandbox skill](https://github.com/yourtablecloth/tablecloth-windows-sandbox) are distributed in separate repositories and are not preinstalled. They require no additional API keys and interpret local reports supplied by a compatible TableCloth host bridge. Certificate checks require user consent and share counts only. Sandbox operations also require compatible Windows Sandbox support. The original AGPL license and commercial-license contact notice are preserved.

The PoC-evaluation-only [everyday calculators](https://github.com/yourtablecloth/tablecloth-calculators) use Python 3.11 or newer and only the standard library. The script calculates from user-supplied values without API keys, external data queries or package downloads. The current TableCloth chat does not supply its required script-execution path, even when a runtime is installed. `Network="none"` describes the calculation script, while Codex chat still uses its normal online connection. The pinned repository's [copyright policy](https://github.com/yourtablecloth/tablecloth-calculators/blob/877b58cf0741db21342445f2b3fcb54ad1ada85c/docs/COPYRIGHT.md) remains applicable to that candidate.

## Validation and publication

[SkillCatalog.xsd](SkillCatalog.xsd) requires immutable references and license sources, limits the catalog to 256 active entries and rejects review attributes. [checkskills.cs](../src/checkskills.cs) also limits the XML to 512 KiB, checks source paths and requires each license URL to match the source repository and commit. Directory segments may contain internal dots but cannot end with a dot; the root marker `.` remains valid. The application separately bounds downloads, rejects symlinks, submodules and nested `SKILL.md` files, and verifies Git blob identities before installation.

Run `dotnet run --file src/checkskills.cs -- docs/SkillCatalog.xml docs/SkillCatalog.xsd` and `dotnet run --file src/testskills.cs -- docs/SkillCatalog.xsd` from the repository root. The latter also guards the currently qualified IDs and pinned sources; update it with the [qualification record](SKILL_ELIGIBILITY.md) when that set changes. The [PR workflow](../.github/workflows/skill-catalog.yml) and [Pages workflow](../.github/workflows/publish.yml) run both checks. The existing catalog builder copies `docs` to the Pages output, publishing the XML at `https://catalog.yourtablecloth.app/SkillCatalog.xml` without requiring a client-side Git checkout. These checks do not execute upstream skills.
